# Architecture Transformation Toolkit

This directory contains the practitioner instruments supporting [AO-ATP-003 — Architecture Transformation Toolkit](../../transformation/AO-ATP-003-architecture-transformation-toolkit.md).

## How to use the toolkit

Start with a bounded business or operational outcome, not a technology choice. Establish what is known, observed, approved, inferred and unresolved. Select instruments based on the questions that must be answered; do not complete every template mechanically.

Recommended sequence:

1. [Instrument catalogue](./instrument-catalogue.md) — select the analysis instruments.
2. [Decision frameworks](./decision-frameworks.md) — evaluate work and architecture dispositions.
3. [Transformation patterns](./transformation-patterns.md) — compare reusable design approaches.
4. [Methods and tools](./methods-and-tools.md) — choose suitable methods and tool categories.
5. [Templates](./templates/) — capture the resulting evidence, decisions and plans.

## Usage principles

- Use canonical upstream identifiers and versioned references where available.
- Keep business semantics distinct from software realization.
- Separate work disposition from architecture disposition.
- Record alternatives, evidence, rationale, ownership and unresolved questions.
- Do not use arbitrary scores or weights without a separately justified and calibrated assessment method.
- Treat tool output as bounded evidence, not automatic truth.
- Distinguish fixture, simulated, test, pilot and live evidence.
- Do not infer production readiness or outcome realization from design artefacts or successful tests alone.

The templates are starting points. Tailor them to the engagement while preserving the distinctions and evidence fields necessary for traceability. They are not normative schemas and do not replace the governance processes of participating programmes.
